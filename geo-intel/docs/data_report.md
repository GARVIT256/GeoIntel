## Reflectance offset diagnostic

`earthsearch:boa_offset_applied` is Earth Search's item property indicating whether its -0.1 BOA correction is already applied to the COG pixels. The [Element84 Earth Search issue discussion](https://github.com/Element84/earth-search/issues/24) describes this property; [issue #66](https://github.com/Element84/earth-search/issues/66) records cases where the flag appeared inconsistent with pixel values. Earth Search's [Sentinel-2 collection documentation](https://github.com/Element84/earth-search#gainoffset-in-items-after-jan-25-2022) says `raster:bands.scale` and `raster:bands.offset` define the transformation, with offset applied after scale. Because these fields can conflict, this project treats the per-item flag as controlling the specific -0.1 correction and checks the result empirically with `scripts/check_offset.py`.

Code-path assessment: before the current fix, the pipeline applied `raster:bands.offset` unconditionally when scale metadata existed, including when Earth Search marked the COG offset as already applied. That could double-apply -0.1. Current code suppresses that declared -0.1 when the flag is true, and applies it once when the flag is false (using the processing-baseline fallback when the asset metadata omits it). This is a code-level rule only; same-tile 2018-12-01 baseline 00.01 vs 05.00 B04/B08/B11 window means and differences: **NOT YET RUN**. No reflectance means or offsets are inferred here.

For Planetary Computer items, `earthsearch:boa_offset_applied` is provider-specific and may be absent. Absence is **not** treated as `false`: the transform uses the asset's declared `raster:bands.scale` and `raster:bands.offset` as-is (defaulting only missing metadata fields to the current pipeline defaults), and does not infer an additional -0.1 offset from the processing baseline. This follows the [STAC Raster Extension](https://github.com/stac-extensions/raster), which defines scale as the multiplicative conversion and offset as the additive conversion after scaling. A live lookup of the Planetary Computer item `S2A_MSIL2A_20241209T053221_R105_T43RGP_20241209T082353` found no `raster:bands` field on B04; this is an item-level observation, not a claim about every PC item or band. [Item STAC JSON](https://planetarycomputer.microsoft.com/api/stac/v1/collections/sentinel-2-l2a/items/S2A_MSIL2A_20241209T053221_R105_T43RGP_20241209T082353). The collection catalog describes the dataset but does not define the Earth Search-specific flag. An absent-flag fixture case checks the pipeline behavior; it is not evidence about reflectance values.

All-retained-scene offset diagnostic: **NOT YET RUN**. `scripts/check_offset_all.py` accepts manually selected, visually confirmed dark/dense and bright target centers as WGS84 lon/lat, converts each center to a fixed 1 km square in EPSG:32644, and prints the converted bounds. It reads both windows for every deduplicated T1/T2 item, prints item transforms and B04/B08/B11 medians, flags per-band item/epoch-median differences over 0.03, and summarizes false-versus-true flag group steps. It also compares every retained same-tile, same-calendar-date item pair at those common windows and marks pairs whose flags differ. Windows and all measurements remain **NOT YET RUN**; no target type or reflectance result is asserted.
